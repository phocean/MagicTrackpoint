# Audit final de MagicTrackpoint 1.0.0 — synthèse des trois audits

Commit audité : `7e27182` (release v1.0.0). Trois auditeurs indépendants, chacun
sur sa propre copie du dépôt, en lecture seule, avec la même consigne (qualité,
sécurité, architecture) :

| Auditeur | Moyen | Rapport brut |
|---|---|---|
| Codex (codex-cli 0.171) | `codex exec`, bac à sable `read-only` | [2026-11-22-codex.md](2026-11-22-codex.md) |
| Claude | sous-agent, lecture seule | [2026-11-22-claude.md](2026-11-22-claude.md) |
| Grok (grok 1.0.92) | `grok`, bac à sable `read-only`, recherche web coupée | [2026-11-22-grok.md](2026-11-22-grok.md) |

Aucun n'a lancé le démon ni touché au matériel : ce sont des audits du code.
Chaque constat ci-dessous a été **revérifié dans le code par le chef de
projet** ; la colonne « Verdict » dit ce qui est prouvé, nuancé ou écarté.

## 1. Ce que les trois confirment (points forts)

- Exigences de sécurité du cahier des charges tenues dans le code : jamais en
  root, aucun réseau, aucune mise à jour, aucune collecte, aucun certificat
  généré, API publiques uniquement, journal sans donnée de saisie, les touches
  du clavier rejetées à la première comparaison sans copie ni journal.
- Cœur pur (`mtp_core.h`) bien testé, lecture de configuration robuste
  (taille bornée, un seul descripteur, types stricts).
- Chaîne d'installation soignée (écritures atomiques, plist échappé puis relu,
  configuration jamais écrasée) et de publication solide (Developer ID,
  horodatage, notarisation, agrafage, Gatekeeper).

## 2. Constats consolidés

## 3. Plan de correction proposé (version 1.0.1)

1. **B1** : remettre `owedWheel` à zéro peu après la fin du geste (délai unique
   déclenché par le relâché, pas une scrutation).
2. **B2** : en Bluetooth, terminer le geste quand le rapport `0x02` dit
   « bouton relâché » alors qu'il l'avait vu enfoncé ; à valider par une capture
   sur le clavier.
3. **B3** : revérifier `AXIsProcessTrusted()` à chaque début de geste et au
   réveil ; si elle est perdue, remettre le firmware en mode natif et écrire
   `accessibility=MISSING`.
4. **B4** : nouvelles tentatives hors des rappels d'entrée, différées et
   bornées, jamais pendant un geste ; couper les deux filtres pendant une
   écriture.
5. **B5** : `scroll.enabled` invalide → `false` (échec fermé).
6. **S1, S2** : épingler l'équipe Developer ID dans `install.sh` (injectée par
   `make-dmg.sh` depuis l'identité de signature) ; copier le binaire dans un
   dossier privé, vérifier cette copie, n'exécuter et installer qu'elle.
7. **D1, D2** : selon l'arbitrage du client (ci-dessous), puis aligner README,
   architecture et feuille de tests.
8. **T1, T2, A1** : corriger la documentation ; déplacer la logique B1–B4 dans
   le cœur avec des tests ; retirer les étiquettes et contrôles vides.
9. **S3, A3** (optionnel) : la désinstallation propose de retirer les entrées
   TCC ; firmware remis en mode natif à la mise en veille.

## 4. Arbitrages demandés au client

- **D1 — scrutation.** Recommandation : garder la revérification **uniquement
  pour l'Accessibilité** (la seule que le démon peut voir changer sans
  redémarrer), n'écrire le statut que s'il change, et l'inscrire comme
  exception explicite au « sans polling ». Alternative stricte : supprimer le
  minuteur ; il faut alors relancer (`magictrackpointctl permissions`) après
  chaque autorisation.
- **D2 — autres souris pendant un geste.** Recommandation : garder le filtrage
  (sans lui, le TrackPoint produirait des doubles défilements et des clics
  parasites), corriger B1 pour qu'il ne déborde jamais du geste, et réécrire la
  promesse du README pour dire exactement cette limite.
